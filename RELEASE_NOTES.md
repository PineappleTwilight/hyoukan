### New

- **App icon and name personalization**: Settings → Appearance → **App icon & name** offers six built-in launcher icons (Forest, Midnight, Sakura, Ocean, Ember, Paper) that switch instantly, plus a custom-image picker with a **Crop / Fit** choice — crop fills the square by trimming the edges, fit keeps the whole image on a transparent square. Because Android does not allow an installed app to replace its own launcher icon at runtime, the custom image is added as a pinned home-screen shortcut that carries both the image and any custom name you set; the About screen also shows the custom name. Built-in icons are declared as activity aliases, so adding another stock icon later needs only a manifest alias, a mipmap, and one entry in the icon list.
- **Delete downloads in bulk**: Settings → Data and storage gains two confirmed cleanup actions — delete the downloaded chapters of every entry that is no longer in your library, or wipe every downloaded chapter on the device. Library entries, bookmarks and reading progress are kept; failed downloads are removed with the rest.
- **Visible Cloudflare challenges**: when a site throws a challenge that needs a human — a Turnstile checkbox — while you are using the app, it now opens in a popup you can actually solve instead of the request failing after 30 seconds with an error. The popup loads the challenge with the app's own user agent and the resulting clearance cookie is reused by the app, and concurrent requests to the same site wait on the one popup and resume together once it is solved. What happens while you are away (library updates, downloads) is unchanged — those still solve invisibly.
- **Built-in Komga source**: browse, search and read straight from a Komga server without installing an extension. EPUB books open in the book reader (downloaded to the app cache once, then read offline), comics read as image pages, and reading progress syncs through the existing Komga tracker. Configure the server address (and optional API key) in the source's settings.
- **Page-turn animations for books** (paged reading): the old page now slides off the edge you are heading for, dissolves, or swings over on its spine — with an adjustable speed. Off by default; pick one in Reading appearance → Page turn.
- **Footnote popups in books**: tapping a note reference now shows the note beside the text — a small window wearing the book's own typography, images included — instead of turning to the notes document. Notes that live in another file are read out of the book on the spot; anything that cannot be shown falls back to the ordinary link behaviour. Toggleable in Reading appearance.
- **Auto-scroll for books** (continuous reading): the page scrolls itself at a pace you set — dp per second, from a slow drift to a brisk walk — pausing the moment you touch the screen, and running off the end of a chapter exactly as a finger drag would. In paged mode the same toggle becomes Moon+'s timed page-turn.
- **Word spacing and text-outline** settings for books (Reading appearance), alongside letter spacing and italic — Moon+ Reader's typography set, engine-native.
- **Status line for books**: a quiet line at the top or bottom of the page showing the clock, your progress through the chapter, the chapter's name and the battery level, each toggleable, with its own size and colour. Off by default.
- **Webnovel plain-text support**: sources that serve chapters as plain text now render as real paragraphs — line breaks become paragraph breaks, and three cleanup passes (intelligent paragraphs, blank-line removal, space trimming — Moon+ Reader's suite) strip the artefacts of machine-assembled text. Each pass is toggleable in Reading appearance → Webnovels.
- **Highlights and selection actions in books**: select any text to get four pen colours, a copy action and a look-up (the system web search, or ColorDict/GoldenDict when installed). Highlights persist per chapter, survive font changes and reflow, and re-mark themselves on every page. Tap inside a highlight to remove it. Toggleable in Reading appearance.
- **Read-aloud for books**: the window's text is spoken by the system text-to-speech engine, in order, with an adjustable rate — and it chains across the book, turning the page itself when a document is spoken out (works in continuous and paged modes). Reading appearance → Read-aloud.
- **Ignore publisher styles** for books (Reading appearance): drops the book's own stylesheets and keeps the reader's — the escape hatch for books that hardcode pixel font sizes, page-width boxes or paper-tuned letter-spacing. Your typography settings win from the first page, and flipping it back restores the book's styling instantly.
- **Upscale new entries by default and per category**: the AI upscaler's per-manga toggle gains two wider controls - a category default (on/off per library category, with the per-manga toggle still winning) and an opt-in default for newly added entries - so whole collections can be upscaled without touching each entry.
- **Prefetch upscaling ahead of the page you read**: the next pages are upscaled into the cache while you read, so turning the page shows the sharpened image instantly. Depth is adjustable (0-5) in the upscaler settings.
- **Import your own ONNX upscaler models**: pick any .onnx file; it is validated by the runtime before acceptance and usable as the NPU/CPU engine's model.
- **Live upscaler status**: the upscaler settings screen now shows what actually happened - served pages, cache hits, fallbacks, failures, average inference time and per-backend readiness.
- **AI upscaling for everyone**: native model upscaling (Real-CUGAN / Real-ESRGAN / Waifu2x) no longer requires AI Translation — every build and device can now upscale, falling back to a plain resample when models are not installed.
- **Upscale category defaults**: choose per category whether its entries get upscaled (on, off, or no override), with the per-manga toggle still winning over everything.
- **Prefetch pages ahead while reading**: the next pages are upscaled in the background before you reach them, memory-gated so low-RAM devices keep the page turn smooth.
- **Bring your own upscaler**: import your own ONNX super-resolution models from storage — they are probed by the runtime before acceptance and join the fallback chain like the built-in ones.
- **Discord RPC: log in with a token.** The Discord login screen's menu now takes a raw account token directly, validated against Discord and stored locally — a way in when the embedded-WebView login is flagged or fails.

- **Komga extension: EPUB books can be read in-app again.** With **Delegated sources** turned on in Settings → Advanced → Developer tools, an installed Komga extension is served by the app's own Komga implementation: series that contain real EPUBs are listed in full, and those books open in the book reader instead of being hidden. The server address and credentials you entered in the extension are used as-is, and existing library entries and Komga tracker links keep working.


### Improve

- **Reader: the high-quality WebGPU renderer is now the default, and no longer withheld from low-memory devices.** It used to fall back to the standard viewer on any device below a fixed RAM class, even where WebGPU itself worked, and it was off unless you found the switch under Settings → Advanced. It is now offered wherever the device supports WebGPU and is on by default, the reader's existing memory budgeting sizes pages and tiles to the device, and a device whose GPU device keeps dying still falls back automatically after repeated dead sessions (the switch's summary says so when that happens).
- **Settings search now finds the setting you mean.** The settings hub opens with a search row, and the search itself indexes every settings screen instead of only the hub's main categories — Discord, webhooks, achievements, the MTL engine sub-screens and the launcher identity screen are all reachable — matches screen titles, group headings, row titles and summaries, searches all words in any order ("black theme" finds the AMOLED switch), and no longer stops at ten results.
- **The upscaler page reads like a settings page.** Its controls are grouped by the decision they belong to (quality, performance, cache, models, library categories), all labels are translated, the live status lines are compact secondary text, and per-category defaults are proper "Inherit / Always upscale / Never upscale" rows instead of a tap-to-cycle loop.
- **Book settings’ import row is inset like the rest of the screen**, instead of the summary and button sitting flush against the edge.
- **The achievements screen scrolls as one list.** The achievement grid was an 800dp inner scroller inside the settings list, so it captured the page's scroll and left a band of empty space on short screens; it is now a plain two-column flow of cards inside the same scroll.
- **Translation sessions, the per-manga translation cache, and the MangaTranslator account screen now have proper app bars** with back navigation and correctly labelled actions ("Stop" rather than "Kill"), and their copy and progress rows are translated and padded consistently.
- **One image decoder instead of two.** The app now decodes every format it handles through the upstream libvips decoder; the older Mihon decoder and its duplicate native library are gone. Crop borders keep working — the page frame is trimmed after decode now rather than inside the native call.
- **Battery: the reader's display no longer sits at its highest refresh rate while you read.** The hardware-accelerated reader used to pin the panel to its fastest mode the whole time it was open, which on a 120 Hz phone means the screen redraws twice as often as it needs to for a page you are simply looking at. The top rate is now requested only while something is actually moving — a scroll, a page turn, a zoom — and released the moment it settles, so the panel can drop back on its own. Reading feels identical; the difference is what the display is doing underneath.
- **Battery: the reader stops polling memory when nobody is looking at it.** The reader re-checked the device's memory four times a second for as long as it was open, including overnight with the screen off. It now backs off to a slow cadence when the reader is stopped or the screen is off, and backs off further when memory has been critically low for a while instead of re-reading a device that is already being reclaimed. Memory still reacts instantly to a real trim signal — only the polling slows down.
- **Battery: fewer background wakeups while you read.** Four small timers used to keep firing regardless of whether they could do anything: the book reader's status line re-read the clock every 30 seconds even when only the chapter name and progress were selected (it now ticks only when a field actually needs the device), the decode stall watchdog checked every second even with no page decoding (it now parks while nothing is in flight), and auto-scroll polled ten times a second while the menu was open (it now waits for the menu to close). None of these change what you see — they just stop waking the device for nothing.
- **Battery: books release their in-memory work under memory pressure.** The book reader's two derived caches — inlined documents (which base64-encode every illustration a page reads) and font rules (a bundled font is half a megabyte spelled as text) — are now dropped when the system says memory is short, instead of being held for the whole session. Both are rebuilt on the next render, so nothing the reader is looking at is lost.
- **Memory: one shared budget across the whole app, instead of a separate guess in each corner.** The reader already sized itself to the device; now the same device tier and live memory pressure govern the image cache, the JXL/AVIF decode limits, how many images load at once, and whether the AI-translation and high-quality-reader gates admit a device. A phone is now treated the same way wherever you are in the app, so a device can no longer be "low memory" in the reader and "plenty of room" on the library screen.
- **Memory: pages that need the heaviest decoding are handled more consistently.** Very large JXL/AVIF pages are now capped by what the device can actually hold at that moment rather than by a fixed device-size switch, so the same page is decoded the same way on the same device whether memory is plentiful or tight — and the same page no longer succeeds on a small phone while crashing a large one.
- **Reader: images keep their full colour whenever memory allows.** The old rule quietly downgraded large images to a lower colour depth on anything under 3 GB, which showed up as banding on gradients. The decision is now made per page against live memory, so a device with room keeps full colour at any page size, and the downgrade is reserved for when memory is genuinely short.

- **Reader: diagnostics now travel with the log dump.** Settings → Advanced → Dump crash logs now includes a short WebGPU session summary — what the reader decoded and how long it took, how tight memory was, whether pages were downsampled or evicted, whether a decode stalled, and whether the GPU device was lost. A problem report can now carry what the session actually did instead of only "the reader is broken".

- **Granular extension content warnings replace the single NSFW toggle.** Extensions can now be flagged Safe, Mixed or NSFW (an extension's sites can carry more than one label), and you choose which warnings you allow in Settings → Browse — several at once. The old "show NSFW sources" switch migrates to the new setting; everything you had enabled stays visible.
- **MangaDex and the remaining delegated sources have been removed.** MangaDex (including its login, follows sync and recommendations) plus the NHentai, 8Muses, Pururin and LANraragi in-app sources are gone — only E-Hentai/ExHentai and the built-in Komga source remain. Library entries from the removed sources are kept and their metadata remains readable; MDList (MangaDex) tracker rows are cleaned up on upgrade. If you read from MangaDex, install the community MangaDex extension instead.
- The discontinued Mullvad DNS-over-HTTPS option has been removed from the DNS-over-HTTPS picker; anyone on it is switched to the default automatically.
- **Reader: WebGPU gesture fixes from upstream.** A tap while a page is still settling now continues from where that motion was heading instead of jumping to the page's rest position, and a double-tap zoom in the long strip keeps its pan clamped as it zooms instead of snapping back afterwards.
- **Reader: long-strip flings start from the finger lift.** The decay is timed from the moment you let go, like a scrolling list, so the strip no longer pauses for a frame or two and then jumps.

- **Non-crash problems are now diagnosable — without eating storage by default.** The app keeps an in-memory logcat ring that survives process death and is flushed on demand (crash or "Share crash logs"), so the tail that explains a silent failure is there when you need it. At the default **Minimal** level warnings and errors are kept, and nothing is written to disk; continuous file logging (and the full debug/network detail) is opt-in via **Settings → Advanced → Log level**. The ring is bounded by both line count and a byte budget that tightens on low-RAM devices (down to 1 MB / 500 lines), so it never competes with the reader for memory. A new **View logs** screen (Advanced → View logs) lets you browse, copy, and share past crash/dump files without `adb`, and **Clear logs** wipes crash files, the ring, and the system buffer in one tap.
- **The app log file is now written even on a fresh install.** Previously the XLog file printer was silent until you configured a storage directory; it now falls back to an app-private log folder so a bug report always has app-side logs to attach.
- **The crash screen now shows the full report** (stack trace + debug info) instead of only `exception.toString()`, and the crash-loop guard tolerates a burst of crashes before giving up instead of only adjacent ones.

- Tapping the version entry on the About screen now copies the full device info block (the same one crash reports lead with), not just the version line — bug reports finally arrive with a device to reproduce on.
- Extension update errors are now only recorded for HTTP 401 and 404 — the statuses that mean the source needs your attention. The rest (Cloudflare challenges, rate limits, server hiccups) are logged but no longer flood the errors screen, and any recorded HTTP error's message tells you to check the site in WebView.
- Migration: **"Fetch chapters in manual search" is now off by default** — each result's latest-chapter lookup is opt-in traffic, and slow sources no longer leave every result card spinning.
- Books: turning pages now reports what the layout engine actually answered, so a "pages don't turn" report can be diagnosed from the log.

- **Books: the font picker now has a scrollbar** — the bundled and imported families overflow the dialog, and the list gave no affordance for that.
- **Anime-Planet tracker search works again.** The site now fronts its search page with a Cloudflare bot check; the tracker used to read that interstitial as the search result (empty "no results", or a long spin) instead of waiting out the check. It now waits for the real page — and if the check never clears, the error names the likely cause instead of a raw timeout message.
- **Beta builds now log what the Discord RPC is doing.** The RPC logs through Timber, which was only planted in debug builds — every RPC failure (including the external-asset errors behind a missing presence image) was silent outside debug. Logging is now planted in every build, external-asset failures are mirrored into the in-app log, and successful image conversions are cached so the rate-limited endpoint is asked once per image instead of on every presence update.
- **Beta builds are now release builds with a beta tag.** The beta channel had been shipping the unminified debug build, which is why a low-end device could spend 30-40 seconds opening the beta where the stable release took ten. Betas are now built from the same minified, shrunk preview variant as a release and published automatically from `master`, and a beta install checks the beta repository for its updates. Existing beta installs need one manual install to move over: the new build has its own application id and signing key.
- **The WebGPU reader now records degraded sessions in the in-app log** — when a session ends with a dead or parked renderer, the strike (and what it means for future launches, up to the automatic fallback to the standard reader) is written where a phone-only user can actually see it.
- SyncYomi protocol v2 is available as an opt-in: server-side merge and delta sync, with automatic fallback to v1 when the host does not advertise v2
- SyncYomi manga `version` now bumps when an entry's categories change, and no longer bumps when chapters are read (chapter progress is versioned on the chapter itself)


### Fix

- **Pages no longer go black when the tiled renderer is enabled.** The page and its background were drawn in a render pass that carried a stencil attachment for the tile overlay's masking. That masking no longer has a consumer — the page is painted under the tiles on every frame — but the attachment left the page's visibility at the mercy of the driver's stencil handling: the 24 Nov Mali-G76 and PowerVR dumps show a correct page quad, a presented frame, `errs=0` and a black screen. The paged page pass now has **no stencil attachment at all** and draws with the stencil-free pipelines, so no stencil state can discard it on any driver. The tile overlay still blits over it for sharpness. The session report also reads back the first page texture's centre texel (`tex=rgba=…`), so a report can now distinguish a black texture from a black composite instead of showing `tex=none`.
- **A page can no longer be hidden by a tiled renderer that reported "fully painted" after drawing nothing.** The tiled path answers the page "did I cover the whole screen?" so the page can skip drawing itself — and that answer was trusted absolutely, so any wrong answer (a placement that collapsed to an empty rectangle, no instance buffer, a tile count over its buffer) or any blit whose pixels did not land left the page invisible with no error. **The page is now painted under the tiles on every frame** and the tile cache blits over it: tiles still supply the sharp cut, but a page can no longer be missing from the frame because of anything the tile path answers. A "covered" answer now also requires an actual blit.
- **The WebGPU reader's session report now says whether the display was ever written.** The old `drawn` flag is set by the reader's page walk *before* a frame is submitted, so a session that never reached the screen could still report `drawn=true` — exactly what happened in the 22 Nov black-screen report. The report now carries `frames=`, a count of frames the renderer actually submitted and presented, and a session that decoded pages for more than five seconds without both a presented frame and a page on screen is treated as the black-screen shape, so the reader falls back to the standard viewer instead of repeating it silently.
- **Sharing a log dump no longer logs a `SecurityException`.** The share sheet's target list is read by the system (uid 1000) to build the file preview, and the read permission was attached only to the inner share intent, so every share produced `Permission Denial: reading ... FileProvider ... requires the provider be exported, or grantUriPermission()` in the log. The read grant (and the URI's ClipData) now travels on the chooser intent as well, so the preview works and the noise is gone.
- **WebGPU reader on PowerVR-class devices: pages no longer stay black when the driver rejects part of the render path.** Three separate failure shapes are now survivable: a wedged display surface is actually rebuilt (the viewer used to stop retrying after ten frames, below the thirty the rebuild needed), a page whose tiled path throws now falls back to drawing itself directly instead of failing the whole frame, and a frame whose draw throws is no longer reported as successfully drawn (which had made a permanently failing pipeline look like a healthy session). The same report now also includes the GPU backend and the renderer/driver log lines, so a device-specific failure can be diagnosed from a normal in-app log dump.
- **WebGPU reader: a display surface that stays black is now fixed instead of only reported.** On some PowerVR drivers the display surface can come up broken — every frame asks for a new image and gets an error, while the renderer still believes it configured the surface — and rebuilding just the surface reproduces it. The reader now escalates: rebuild the surface, then restart the GPU stack (a fresh Dawn instance and device), then switch the adapter to the OpenGLES backend (a different display path entirely), and only then give up for that session. The surface is also configured with the display format the driver actually reports rather than a hardcoded one, a reconfigured surface waits one frame before its first image request, and the error path no longer reconfigures the broken surface on every single frame. The reader also shuts its GPU surface down before the next chapter opens, so a new session no longer inherits a surface the previous one left behind. A session that recovers says which step did it in the log.
- **The WebGPU reader now drops device-bound pipeline caches when the GPU device is rebuilt.** A device loss recovered mid-session could leave the page-draw pipelines and bind groups belonging to the retired device; Dawn then rejects every frame (`BindGroupLayout … associated with [Device]`, `Invalid CommandBuffer`), so the reader presented frames and showed nothing (reported on a Mali-G76). The page renderer's caches — the background, circle, line and text pipelines, and the font atlases — are now cleared as part of the rebuild, an uncaptured validation error is reported as a failed frame instead of a drawn one, and the session report carries an `errs=` count. The one-shot page-texture readback logs `tex=rgba=…` in the report.
- **PowerVR pages now render through the tiled path.** The tile cache was disabled on PowerVR as a black-screen workaround, but the black frames came from device-bound pipelines and font atlases surviving a device rebuild, not the tile atlas. With the tile path restored, halftone screentones no longer moire at the reader's ~0.6 display scale (the path minifies with a box filter instead of one bilinear tap), and page transitions run again because they seed their caches from the tile atlas. The direct page draw stays as the fallback if a tile pass ever throws.
- **PowerVR devices now draw pages through the linear-light page shader.** The direct page path (the only one PowerVR uses, since its tile cache is disabled) was selecting the cheaper plain pipeline; on the GE8322 that pipeline rendered nothing while the same page and geometry rendered on the Mali-G76. The direct path now uses the same linear shader as the tiled path, and the settings pin `ca.mpreg:webgpuviewer` explicitly to the in-repo fork so a published Maven artifact can never be substituted for it.
- **WebGPU reader: the high-quality renderer no longer silently disappears on minified builds.** In some beta builds the native WebGPU library had not been loaded when the renderer first asked for a GPU instance, so the reader fell back to the standard viewer with the reason "No implementation found ... createInstance" in the log. The library now loads the native runtime directly and retries that first call once, and the build keeps the WebGPU classes that the JNI symbols bind to — so the renderer opens instead of quietly falling back.
- **Adding an extension store from an "add repo" link now works on a cold start.** The link could arrive before the store list had loaded, and the confirmation dialog was silently discarded — so nothing was added until you restarted and opened the screen again. The request is now held until the list is ready, and the add survives leaving the screen before the write finishes.
- **The More tab and the App icon & name screen no longer crash on Android 11-era devices.** Both built the app-icon manager, which asked Java for its own class package through an API Android only carries on newer releases; the lookup failed and took the screen down. The package is now derived from the class name, which every supported Android version understands. The custom name itself was never applied to the installed launcher label — Android does not allow that — so nothing here depends on the OS accepting a runtime rename.
- **WebGPU reader: "Disable zoom in" now actually disables zooming in.** With the setting on, a pinch or a double-tap (including the drag after a double-tap) could still zoom, and pages opened after the setting was enabled ignored it entirely. The maximum scale is now tied to each page's own fit scale the moment it is laid out, and the pinch and double-tap-drag gestures respect that ceiling while your fingers are still down instead of springing back afterwards. Zooming out and the double-tap-zoom setting are unchanged.
- **The WebGPU reader no longer falls back to the standard viewer by itself.** The app remembers sessions in which the GPU renderer failed and, after two of them, quietly opened the standard viewer — while the WebGPU settings stayed visible, which is why it read as "the renderer just stops working". A session that ended on a chapter transition counted as a failure even though every page had drawn, so finishing two chapters and closing the reader was enough to switch the renderer off for good. That verdict now comes from what the session actually drew, the remembered failures are cleared by every new build, and switching the high-quality renderer off and on clears them too — so a fixed build gets a fresh try instead of inheriting an older one's verdict. When it still has to fall back, the reader now writes the reason to the in-app log.
- **E-ink: pages no longer reveal themselves as a ripple from the middle of the screen.** The tiled renderer cuts tiles in a centre-out order and used to paint each one as it landed, which on an e-ink panel looks like a wave of partial refreshes spreading outward every time a page opens or sharpens. A page at rest now stays on the fast full-page draw until every visible tile is ready and then switches once; while you are panning or zooming, tiles still appear as they arrive.
- **The reader no longer crashes while the upscaler's category settings are first read.** A background listener in the upscaler's configuration could run before its cache existed, producing a `Null reference used for synchronization` crash on some devices just as a chapter opened. The cache is now created before that listener can start.
- **WebGPU reader: the Webtoon group's switches now reach it.** Three settings in that group were read only by the legacy viewers, so they changed nothing while the hardware-accelerated reader was open: **Viewer navigation** (tap zones — the Pager group's zones were used for every mode), **Crop borders** (the Pager switch was used for every mode), and **Side padding** (ignored entirely). Tap zones and crop borders are now resolved per reading mode, and side padding draws the strip in a narrower, centred column. One setting is deliberately *not* implemented: **Scale type**, which is defined against a paged viewer the WebGPU reader does not have — a fixed column would have narrowed every page, including the long strips the setting exists to leave alone.

- **Blacklisted chapters stay hidden.** The chapter blacklist was stored in a list whose separator can also appear inside the stored keys (scanlator names like "Group A, Group B", or a pinned upload's address), so reading the entry back lost the very key that was written and the chapter reappeared. Blacklists are now stored losslessly; entries blacklisted on older builds keep working. Three more ways the same symptom could come back are closed: the library badge and the History tab now recognise both storage formats, so blacklisted chapters stop inflating their chapter counts; blacklisting a chapter and immediately leaving the entry no longer cancels the save; and blacklisting several chapters in quick succession no longer drops the earlier ones.
- **Rotating achievements now announce themselves again.** The rotating achievement toast did not fire when a tier completed.
- **The Discord RPC settings no longer crash the app on open.**
- App: fixed a `NoSuchMethodError` crash (`HttpException.getCode`) that killed the whole app when an extension hit an HTTP error — the 1.25.3 package shipped an inconsistent build of that exception class; any build of the current sources resolves it.
- **Custom covers now travel with backups**: an entry's custom cover image is stored inside the backup itself and restored on any device, instead of living only in the app's cover cache that backups never carried. Toggleable under Create backup → Custom covers (on for manual backups; off for sync, so sync payloads stay light).
- **Paged reading no longer crashes on large pages.** The paged viewer's tiled image decoder was built against the image-decoder library the app no longer ships (it moved to a single upstream decoder), so any page big enough to be cut into tiles — the tall and high-resolution ones — closed the reader with `NoClassDefFoundError: tachiyomi.decoder.ImageDecoder`. The app now supplies the small compatibility layer that decoder needs over the one decoder it does ship, so those pages open again, with crop-borders still trimming them.
- **The database is no longer touched by a second SQLite connection.** Startup maintenance and database export open the live database a second time to run their integrity check and checkpoint — through a different native SQLite library than the one the app itself uses. While the database is in WAL mode that second connection cannot share the live connection's `-shm` file and fails with `SQLITE_IOERR_SHMOPEN` (`POSIX Error: 9`, lock owner `-1431655766`), which showed up as logcat noise on every launch and could abort the maintenance pass. Both passes now run their pragmas on the app's own connection, so the check reads the same file state the app is writing.
- **WebGPU reader: the renderer opens again instead of falling back on every device.** Recent beta builds shipped the WebGPU native runtime and its Kotlin classes from two different builds of the same version, so the very first GPU call failed with "No implementation found ... createInstance" and the reader quietly switched to the standard viewer. The renderer now takes its WebGPU dependency the same way Mihon does — the official `1.0.0-alpha06` release from Google's Maven repository, declared once by the WebGPU library and inherited by the app — so the classes and the native library always come from one build.

- **Upscaling no longer requires AI Translation**: the upscaler was rebuilt as its own pipeline (like the translation rewrite) — the no-MTL build now gets native model inference too, the mode gains an Auto option that falls back to simple resampling when a model or backend is unavailable, and existing per-manga opt-ins and the page cache carry over untouched.
- **Real-CUGAN 3x model added**: the upscaler catalog now offers a 3x Real-CUGAN alongside 2x/4x options, with 3x/4x artifacts verified by hash.
- **Reworked the translation pipeline from the ground up** — the on-device translation engine was rebuilt for faster startup, more reliable translations when providers change or go offline, and a smarter cache that reuses translated pages until the source or provider settings change.
- **Title and description translations no longer show stale results** — cached translations are now validated against the manga's current metadata and your provider settings, so edited entries re-translate instead of showing outdated text.
- **Clearer provider status in translation settings** — the Gemini Nano device status row now reflects the actual on-device availability reported by the engine.
- **Legacy translation caches are cleared on upgrade** — one-time cleanup of the old saved-page store; translations of pages will re-run on demand.

- WebGPU devices now run in full core mode wherever the driver supports it (`core-features-and-limits`), instead of staying in Compatibility mode with its lower limits — removes a class of silently-broken pipelines that could draw nothing (black screen) on capable devices.
- Reader: extremely high-resolution comic pages (250MB-comic territory) no longer crash the WebGPU reader out of memory. Pages are now clamped to what your screen can actually show (with zoom headroom) instead of uploading every pixel of a huge scan to the GPU — so the reader survives instead of dying with a lost GPU device mid-chapter, and on small or e-ink panels it uses a fraction of the memory it did. On a struggling device page detail eases off and recovers with available memory rather than the reader failing; 32-bit devices get a deliberately smaller memory budget across the reader.
- Reader: a WebGPU page could render at a tiny fraction of its size (a few dozen pixels) after the surface was rebuilt underneath it — seen on e-ink readers around refresh-mode switches and on sleep/resume: view a page, swipe away and back, and it came back postage-stamp. The degenerate scale is no longer latched; the page returns at its proper size.
- Reader: WebGPU sessions whose GPU device keeps dying without recovering now fall back to the standard reader on the next launches, instead of opening the same black screen every time — the easter egg on the About screen's version entry resets that fallback after a driver update fixes the device.
- **Reader: pages load in the order you read.** The WebGPU reader now ranks its background loading by where you are and where you are heading — the page on screen first, then the side you are scrolling toward — so turning into an unfetched page finds it already decoded far more often, especially right after opening a chapter.
- **Reader: TIFF-based pages are recognised again.** A comic page delivered as a little-endian TIFF was rejected as an unsupported image format before the decoder ever saw it, because the header's byte-order mark was read in the wrong byte order; the page now decodes like any other.

- **Reader: the WebGPU loading placeholder now says what it is doing** — the percentage is joined by the current stage (fetching, decoding, uploading…), so a slow page tells you whether it is waiting on the network or already rendering.
- **Reader: pages reserve their true height before they finish loading** — as soon as the app can know a page's shape (the moment its bytes are read, or — for long strips cut into segments — at the moment they are cut), the loading placeholder occupies exactly the space the finished page will. Turning into an unfetched page or scrolling through a loading long strip no longer reflows the pages around you as they finish.
- **Discord presence art shows again.** The app icon and the manga cover were both sent to Discord as plain image URLs, and only the large slot accepts those — the small one was dropped, so the card rendered with no images at all. The cover now goes through untouched and the icon is left to Discord's own application record. The external-asset conversion behind it is gone: it authenticated with your account token but expects the application's, so it had been failing every time.
- **MyAnimeList login accepts the redirect the bundled client uses.** The callback could land on a scheme the app did not answer, which MAL reports as an invalid redirect. The app now answers the Komikku and Mihon schemes as well as its own, and a fork can ship its own MAL application with `-PmalClientId=...`.
- **Google Drive: the redirect belongs to the build.** The callback address was hardcoded to a name the app does not own, which is why a fork could not use it. It is now a build setting (`-PgoogleDriveRedirect=...`) whose default keeps existing credentials working, and the app also answers its own per-application scheme so a client registered for it works too.
- **Tablet settings: a section can be opened again after visiting a sub-menu.** Choosing a section in the left pane now resets the detail pane to that section, so Connections (or the debug menu, or any other row) is reachable again without leaving settings first.
- **Reader: a WebGPU session that never draws anything now falls back instead of repeating.** Pages could decode and upload while the display stayed black; that session looked healthy to the fallback logic because the GPU device was alive and nothing had parked. A session that ends having drawn no page at all counts as degraded, so after two of them the reader opens on the standard viewer.
- **WebGPU reader: pages no longer stay black after a GPU device rebuild.** A page decoded before a GPU device was replaced could be handed to the replacement device, and the driver rejected the first submit mid-frame — `Destroyed texture used in submit` on Mali, `tex=map failed 4: [Device] is lost` on PowerVR — leaving a black page while the session otherwise looked healthy. The reader now tracks the GPU device generation and discards textures that were bound to a retired device, re-decoding the page on the new device instead of submitting a stale one.
- **Restore no longer sits at 100% for half an hour.** Reconciling trackers ran inside the restore job, and that job's progress notification stays on screen until it finishes — on a large library the rate-limited tracker calls took twenty to thirty minutes after the restore itself was complete. The reconciliation now runs in the background and the notification clears when the restore ends.

- Reader (WebGPU): the first pages of a chapter could "run away" from you while you scrolled down — right after opening, or whenever the display's size shifted (menu bar hide/unhide, foldable posture change, e-ink refresh), any page still loading silently re-sized its reserved space, moving the content under your finger without you scrolling. Loading pages now reserve a fixed height until they decode, so the document only ever moves when you move it.
- Reader (WebGPU): a thin dark line could appear between two pages, rarely, while a neighbouring page was still decoding or just finished (the two painters that redraw those boundary rows each computed the boundary their own way, and the two computations could disagree by less than a pixel). Every boundary painter now shares one chained value, closing the last two ways the line could form.
- Reader (WebGPU): a saved reading position could be re-applied over a chapter that had already changed (a chapter swap or a seek landing while the restore was still waiting for its page to decode). Restores are now invalidated the moment the chapter set changes.
- **Books: paged and two-page reading modes now work.** The layout engine's script had a syntax error that silently disabled itself — and the rest of the reader's page plumbing with it — so picking Paged or Two-page did nothing and every book kept scrolling. All three modes behave now.
- **Books: the reader options sheet scrolls again on first open.** The settings sheet could come up with dead scrolling after entering from the reader menu (worst on the first open of a session); closing and reopening it used to be the only cure.
- **Books: the status line's selected colour now shows as selected immediately** instead of only after closing and reopening the settings, and the status line now paints a solid background so the book's text no longer bleeds through it.
- **Books: the status line's chapter field now shows the section you are reading** (from the book's table of contents, falling back to the document's name) instead of repeating the novel's title everywhere.
- **Books: corrupt downloaded chapters now explain themselves.** A download interrupted by a full disk or a dead storage provider used to surface as "Truncated ZIP file data" or "mmap failed: EINVAL (invalid argument)" every time you opened the chapter. Downloads are now verified the moment they finish — a broken archive is deleted and the download fails with a message telling you to try again, instead of leaving a permanently unreadable chapter behind.
- Reader: a chapter whose very tall page gets cut into screen-sized chunks used to land you at the *end* of that page once the chunks finished loading — the classic webtoon "opened the chapter and I'm at the bottom" bug. Opening it now starts you at the top, where the page began.
- Reader: WebGPU devices that black-screen without ever killing their GPU device (seen on PowerVR 32-bit phones) are now counted and remembered, and the reader falls back to the standard viewer on later launches instead of opening the same black screen again.
- App: installing extensions no longer crashes the app on Android 15+ after the install service's daily background-data budget runs out — the service now degrades gracefully instead of taking the process down.
- Library: completing a series that is not in your library no longer counts toward the "clear the backlog" achievements — the backlog is your shelved pile, so only shelved series can clear it.
- **Smarter update scheduling (ported from Mihon).** Update checks now follow an entry's actual release calendar — fixed weekdays, days of the month, twice-monthly and batch-release patterns — instead of a rough day count, and after a missed or late release the next check keeps counting from the missed date instead of resetting, so a series is checked when its next chapter is actually due. Scanlators you excluded no longer skew the estimate.

- **The download queue now survives a full app close.** Paused and unfinished downloads used to vanish every time the app was killed outright: the queue was rebuilt at startup before the extension sources had finished loading, so every entry failed its source lookup and the persisted list was wiped. The queue now restores once the sources are ready.
- **Tracking: adding a series to a second tracker no longer opens the previous tracker's search screen.** The tracking sheet's sub-screens shared one cached state, so each new tracker search reused the first one's results.
- **The More tab's Updates and History entries work again** when their navbar buttons are hidden — they used to do nothing when tapped from the fallback rows.
- **The extensions tab's first page shows the grid-shaped skeleton immediately** instead of flashing a list layout on first load of a grid-mode source.
- **Content-warning badges no longer appear on the Sources tab** — the labels belong on extension rows only.
- **The browse "Support: …" text now lists only the sources that remain** (E-Hentai/ExHentai and Komga) instead of the removed delegated sources.
- **Tablet: leaving a two-pane settings screen with the app bar's back arrow no longer collapses the layout to the phone arrangement.**
- **Tracker-connect achievements now count trackers that arrived with a restored backup**, not only services logged into on this device.
- **Two settings achievements were granted at startup to users who never touched the setting** (Cutout Connoisseur, AST Searcher) — the watcher seeded from default-on preferences.
- **Backup restore: the "Restoring backup" banner no longer lingers** on screen for up to a minute after the restore finished.

- SyncYomi/sync no longer skips most of the library: entries restored from a backup were missing the favorite stamp the uploader required, so chapter progress never left the device (run **Sync now** once after updating so the full library can upload)
- SyncYomi now applies remote un-favourites and drops chapters tombstoned on another device
- SyncYomi full-library syncs allow up to 5 minutes per request so large libraries stop timing out mid-upload
- SyncYomi no longer fails to apply a sync when tracker/history fields the server omits (proto3 defaults) are missing from the response
- **Downloaded books stay books.** Downloading an EPUB from the built-in Komga source used to fail with "No pages found", because a book has no image page list. The EPUB is now saved as the chapter's download and opened from disk by the book reader, so a downloaded book is readable offline — and a Komga chapter that really is a comic still downloads as pages.
- **Books: wider margins no longer cut words off.** Changing the page margins while a book was open re-applied the margin to the whole page frame as well as the text column, so every line's right edge slid under the clipped edge. Paged books now keep the page frame fixed and size the text column against it, so the text reflows inside the new margins at any width.
- **The crash screen no longer crashes.** Showing a crash report nested a scrollable report inside the screen's own scroll, which Android rejects — the report screen died while displaying the crash, hiding the error that caused it. The report now scrolls in the screen's single column, so a crash shows the real stack trace.

- **Brightness floor prevents black pages after GPU device rebuild.** A brightness setting of -1.0 caused the shader to subtract a full unit from every color channel, clamping all pixels to pure black even though the decoded page was valid. The floor clamps the minimum brightness to -70% (−0.7), which renders dark-but-visible page content. A warning is emitted if the preference falls below −50% (−0.5), surfacing the issue in black-page diagnostics.
- **WebGPU texture readback device-lost detection:** Texture readback failures now detect '[Device] is lost' errors and trigger recovery instead of being silently ignored, preventing black screens after device loss without formal device loss events.
- **Category auto-move on tracker completion now works.** Completing a series via the chapter selector or track info dialog (which use `setRemoteLastChapterRead` rather than the manual status change path) now triggers the category sync that moves the entry to the category bound to the new status, instead of leaving it in its old category or sending it to the default category (issue #94).
